# FITS and WBMP output routing

The CLI previously rejected inferred `.fits` and `.wbmp` output paths before
invoking FFmpeg. Explicit `-f fits` was also missing from the format registry.

FITS now resolves to the dedicated `fits` muxer; WBMP resolves to `image2`.
Explicit format selection continues to override the filename suffix. Output
suffixes are case insensitive, while explicit format tokens retain FFmpeg-style
case sensitivity. `-f wbmp` remains invalid because WBMP is an image codec, not a
standalone muxer name.

These requests use `delegated_faithful`: the original option values and their
order reach FFmpeg unchanged. No native image codec or performance improvement
is claimed. Existing path/protocol rejection, including `concat:`, is unchanged.
